========================================================
9. MOTION LANGUAGE
========================================================

Motion must be systemized.

Do NOT invent a different animation for every element.

STANDARD REVEAL:

opacity: 0 → 1
y: 24–36px → 0
duration: approximately 650–850ms
smooth premium easing

EDITORIAL IMAGE REVEAL:

clip-path/mask reveal
scale: approximately 1.05 → 1
duration: 900–1200ms

HOVER:

translateY: 0 → -3px
image scale: 1 → approximately 1.025
arrow translateX: 0 → 4px

POINTER DEPTH:

max rotateX ±2°
max rotateY ±3°

Never create extreme card tilting.

ROUTE ANIMATION:

gold path draws based on scroll progress.

Use Motion:
- useScroll
- useTransform
- whileInView
- MotionValue
- layout animations

Use React ViewTransition for carefully selected page/shared-image
transitions when appropriate.

Do not use animations merely because they are available.

========================================================
10. REDUCED MOTION
========================================================

Respect prefers-reduced-motion everywhere.

Reduced-motion mode:

- disable nonessential parallax
- disable pointer tilt
- disable route drawing animations
- disable camera movement
- disable 3D object movement
- keep simple opacity transitions
- never remove content

No interaction may require motion.

========================================================
11. 3D SYSTEM
========================================================

The website should FEEL dimensional.

Do NOT turn the website into a Three.js demo.

Approximate guideline:

90% DOM/CSS/Motion
10% WebGL/R3F

PRIMARY 3D MOMENT:

Hero can contain a lightweight Trip Line aircraft / flight object.

Preferred:
- stylized premium aircraft
- metallic/brass/gold material
- subtle environmental reflections
- extremely restrained pointer response
- integrated with flight path

If a production-quality aircraft GLB is not supplied:

DO NOT download copyrighted/random assets.

Use a temporary lightweight stylized geometry or logo-derived
2.5D plane representation.

Build the scene architecture so the final GLB can replace it easily.

3D requirements:

- dynamic import
- no SSR for Canvas
- lazy initialize where possible
- reuse materials/geometries
- compressed GLB
- Meshopt/Draco where appropriate
- lightweight textures
- cap DPR approximately 1–1.5
- use frameloop="demand" when scene does not require continuous animation
- dispose assets correctly
- avoid expensive post-processing
- no unnecessary shadows
- no giant environment maps

Mobile:

Use simplified 3D or static 2.5D alternative by default when needed.

3D is enhancement.
Content must work without WebGL.

33. AUTHENTICATION
========================================================

Use Spring Security.

Use session authentication, not hand-rolled JWT auth.

Prefer:
Spring Session JDBC using PostgreSQL so sessions survive application
restarts and can later work across multiple backend instances.

Cookie:

- Secure
- HttpOnly
- SameSite=Lax where architecture allows
- sensible expiration
- regenerate session on login

Password hashing:
use a strong Spring-supported password encoder.

No passwords logged.

Implement:
- login
- logout
- current user
- change password
- admin-created users
- forced initial password change optional

No public signup.

========================================================

Also apply reasonable rate limiting.

Never rely on client-side Turnstile success alone.

Service

========================================================
48. URL STABILITY
========================================================

Service slug changes must be handled carefully.

Prefer:
- slug is editable before launch;
- warn if changed after publishing;
- optionally store previous slugs later for redirects.

Do not casually break published URLs.

========================================================
49. ACCESSIBILITY
========================================================

Target WCAG 2.2 AA.

Required:

- keyboard navigable
- visible focus states
- no keyboard traps
- semantic headings
- landmark elements
- labels for forms
- accessible error summaries
- aria only where necessary
- alt text
- adequate contrast
- reduced motion
- 200% text zoom support
- correct button/link semantics

Do not make motion, hover, color, or 3D the only way to understand content.

Touch targets approximately 44px minimum where practical.

========================================================
50. PERFORMANCE
========================================================

Performance is a product requirement.

Target field Core Web Vitals:

LCP <= 2.5s
INP <= 200ms
CLS <= 0.1

Treat 75th percentile mobile as the important target.

Images:
- next/image
- responsive sizes
- explicit dimensions/aspect ratios
- preload only real LCP image
- lazy load below fold
- AVIF/WebP when practical

Fonts:
- next/font
- minimal weights
- no layout shift

JavaScript:
- dynamic import heavy interactions
- 3D not included in initial critical bundle
- no unnecessary client components

Hero:
must remain visually strong without requiring a huge video.

If video is introduced:
- optimized short loop
- poster image
- muted
- no audio
- mobile fallback
- never block LCP

========================================================
51. VIEW TRANSITIONS
========================================================

Use React ViewTransition selectively.

Good candidates:

service card/index
→ service detail hero

Do not animate every route.

Transitions must:
- be short
- not delay navigation
- respect reduced motion
- degrade normally when unsupported

========================================================
52. CACHING
========================================================

Public content changes infrequently.

Use sensible caching.

Possible approach:

Next.js server-fetch caching/revalidation.

Public page content:
short ISR/revalidation window.

After publish, support targeted revalidation if cleanly implementable.

Admin data:
never statically cached.

Do not let a CMS publish appear stale for hours.

========================================================
67. PRODUCTION BACKUPS
========================================================

MANDATORY.

Database backups:
daily.

Store copy OFF the VPS in S3-compatible object storage/R2.

Suggested retention:
7 daily
4 weekly
3 monthly

Adjust later based on business requirements.

Also preserve:
- Coolify recovery material
- installation secrets
- deployment configuration where applicable

A backup is not considered trustworthy until restore has been tested.

Perform a documented restore test before production sign-off.

81. MOST IMPORTANT CREATIVE RULE
========================================================

Do not sacrifice the approved art direction just because a normal
React component is easier to implement.

Likewise, do not sacrifice usability/performance just to create a
visual effect.

When deciding between two implementations, choose the one that
preserves:

1. Trip Line identity
2. editorial quality
3. responsiveness
4. accessibility
5. performance
6. maintainability

The final public site should feel bespoke and intentional.

The admin should feel effortless and professional.

The backend should be boring, secure, modular, testable and easy
to extend.
